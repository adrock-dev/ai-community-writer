# 관리자 화면 안내

사내 관리자(`apps/admin-next`)의 **메뉴와 영역이 각각 무엇을 하는 곳인지** 설명한다.
운영자(무엇을 어떤 순서로 하는가)와 다음 개발자(고칠 때 어디를 보는가)가 같이 읽도록 썼다.

## 이 문서를 읽기 전에

다른 문서와 역할이 겹치지 않는다.

| 알고 싶은 것 | 볼 곳 |
| --- | --- |
| 화면 메뉴·영역이 하는 일 (이 문서) | 여기 |
| 라우트 목록만 빠르게 | `HANDOFF.md` §5 |
| API 계약·엔드포인트 전수 | `docs/admin-json-api.md` |
| 왜 이렇게 만들었는가(설계 의도) | `DEVELOPER_CONTEXT.md` |
| 화면 문구가 어떤 코드에 매달려 있는가 | `docs/ui-copy-inventory.md` (생성물) |
| 코드를 고칠 때의 함정 | `CLAUDE.md` |

**이 문서는 숫자와 줄번호를 적지 않는다.** 개수·상한·주기 같은 값은 코드(대부분 `constants.ts`나
환경변수)가 정하고 화면이 그 값을 렌더한다. 문서에 옮겨 적으면 코드가 바뀔 때 조용히 거짓이 된다.
이 저장소는 그 드리프트를 이미 여러 번 겪었다. 화면 문구도 그대로 옮기지 않는다 —
문구의 정본은 `docs/ui-copy-inventory.md`다.

## 1. 화면 지도

사이드바는 네 묶음이다. 「콘텐츠 운영」 안의 메뉴만 **운영 대상(도메인)에 딸리고**, 나머지는 전역이다.

| 사이드바 | 메뉴 | 라우트 | 화면 코드 |
| --- | --- | --- | --- |
| (최상단) | 대시보드 | `/` | `DashboardClient` |
| 콘텐츠 운영 | *(운영 대상 선택기)* | — | `AppShell` |
| 콘텐츠 운영 | 도메인 관리 | `/t/{domain}` | `DomainClient` (탭 8개) |
| 콘텐츠 운영 | 글 생성 | `/t/{domain}/generate` | `DomainClient` (`view="generate"`) |
| 콘텐츠 운영 | 검수·보내기 | `/t/{domain}/posts` | `DomainClient` (`view="posts"`) |
| 콘텐츠 운영 | 작업 큐 | `/t/{domain}/jobs` | `DomainClient` (`view="jobs"`) |
| 자료 관리 | 운전학원 자료 | `/academies` | `AcademyResearchClient` |
| 설정 | 작업환경 | `/settings` | `SettingsClient` |
| 설정 | 관리자 가이드 | `/guides` | `app/guides/page.tsx` (서버 컴포넌트) |

사이드바에 없지만 링크로 들어가는 화면:

| 라우트 | 화면 | 어디서 들어가나 |
| --- | --- | --- |
| `/t/{domain}/drafts` | 격리 검수 | 검수·보내기, 작업 실패 안내 |
| `/t/{domain}/post/{postId}` | 글 상세 | 글 목록에서 제목 클릭 |
| `/academies/{externalId}` | 학원 1곳 상세 | 운전학원 자료 목록 |
| `/guides/[slug]` | 가이드 문서 본문 | 관리자 가이드 목록에서 「열기」 |
| `/integrations` | 연동 설정 | 직접 이동 |
| `/need-domain` | 도메인 없음 안내 | 도메인이 없을 때 자동 |

### 같은 컴포넌트가 두 경로로 뜬다 — 먼저 알아야 할 구조

`글 생성`·`검수·보내기`·`작업 큐`는 **독립 화면이 아니다.** 셋 다 `DomainClient`에 `view` prop을
넘겨 그 부분만 크게 보여주는 **집중 화면**이고, 같은 내용이 `도메인 관리`의 탭으로도 있다.

```
/t/{domain}            → DomainClient (탭 8개 전부)
/t/{domain}/generate   → DomainClient view="generate" → 「글 생성」 탭 내용만
/t/{domain}/posts      → DomainClient view="posts"    → 「검수·내보내기」 탭 내용만
/t/{domain}/jobs       → DomainClient view="jobs"     → 「작업 큐」 탭 내용만
```

그래서 **글 생성 화면을 고치면 도메인 관리의 「글 생성」 탭도 같이 바뀐다.** 한쪽만 고칠 수 없다.
반대로 "탭에서는 되는데 전용 화면에서 안 된다"는 증상은 대개 `view` 분기 쪽 문제다.

## 2. 운영 흐름 — 처음 여는 사람이 밟는 순서

화면이 이 순서를 전제로 배치돼 있다. 건너뛰면 뒤 단계가 빈손이 된다.

1. **대시보드**에서 도메인을 만든다. 운전 도메인이면 지역·키워드 프리셋이 자동으로 들어간다.
2. **도메인 관리 › 원천 데이터**에서 지역자료를 받고 **학원자료를 연결**한다.
   연결까지 눌러야 글에 쓰인다(§5 참조).
3. **도메인 관리 › 글유형/디자인**에서 쓸 글유형을 켠다. 아무것도 안 켜면 후보가 안 만들어진다.
4. **글 생성 › 1단계**에서 후보(슬롯)를 만든다. 여기서는 LLM을 부르지 않는다.
5. **글 생성 › 2단계**에서 「1개 테스트 작성」으로 한 건만 써 본다.
6. **검수·보내기**에서 품질을 확인한다. 게이트에 걸린 글은 **격리 검수**에 있다.
7. 품질이 괜찮으면 2단계에서 개수를 늘려 대량 작성한다.
8. 완성된 글을 **내보내기**(Markdown/HTML)하거나 공개 API로 가져간다.

운영 튜토리얼이 이 흐름을 화면에서 직접 안내한다(`lib/tour.ts`). 작업환경에서 끌 수 있다.

## 3. 화면별 설명

### 3.1 대시보드 `/`

**무엇을 하는 곳인가** — 시작점. 도메인을 만들고, 전체 상태를 가로질러 본다.

**할 수 있는 일**
- 새 도메인 만들기 (업종을 고른다 — 등록된 업종만 허용)
- 도메인 목록과 현황 보기
- **모든 도메인의 작업**을 한 표에서 보기 — 진행·대기를 먼저, 그다음 최신순

**주의** — 작업 큐 메뉴는 도메인 하나만 보여준다. **여러 도메인을 가로질러 보는 곳은 여기뿐이다.**
워커가 하나라 "지금 누가 큐를 점유 중인가"를 알려면 이 표를 본다.

**고칠 때** — `DashboardClient`, API는 `GET /domains`·`GET /jobs`.

---

### 3.2 도메인 관리 `/t/{domain}`

한 도메인의 모든 것이 탭 8개로 들어 있다. 파일 하나(`DomainClient`)가 전부를 담당해 크다 —
탭별 담당 컴포넌트는 같은 파일 안에 있다.

#### 개요

현황 숫자와 "다음에 무엇을 할지" 추천, 튜토리얼 시작 버튼. 담당은 `Overview`.

#### 원천 데이터

**무엇을 하는 곳인가** — 글의 사실 근거가 되는 지역·학원 자료를 이 도메인에 들여오는 곳.

**할 수 있는 일**
- 1단계 · 지역자료 동기화 — 외부 원천에서 지역 목록을 받는다
- 지역 축 직접 편집 (CSV, 고급)
- 2단계 · 학원자료 가져오기 — **「학원자료 연결」**이 실제로 글에 쓰이게 만드는 단추다
- 연결된 학원 목록 확인, 특정 학원 **제외**/제외 해제
- 조사값을 글에 쓸지 설정

**주의** — 학원의 **지역 배정과 셔틀 운행 지역은 연결하는 시점에 계산돼 박힌다.** 원천 자료만 새로
받고 연결을 다시 하지 않으면 예전 값이 그대로 남는다. 화면이 그 상태를 경고로 알려준다.

**고칠 때** — `DomainClient`의 `Academies`, API는 `sync/drivingplus/*`·`academies/link`·`academy-exclusions`.

#### 글 공통 설정

**무엇을 하는 곳인가** — 이 사이트만의 말투·태도, 제외어, 키워드 마스터.

**할 수 있는 일**
- 공통 작성 원칙 편집 (프롬프트에 들어간다)
- 제외어 — 후보 생성·검색·작성 큐·최종 저장 전에 걸러진다
- 판박이 문구 — 게이트가 감지해 다시 쓰게 한다
- 키워드 마스터 편집 / 프리셋 기본값으로 초기화

**주의** — 확인된 데이터만 사용·날조 금지 같은 **안전·데이터 규칙은 이미 코드가 강제한다.**
여기에 다시 적으면 강제력은 안 생기고, 여기서만 전달되는 톤 지시만 희석된다. 화면도 그렇게 안내한다.

**고칠 때** — `Principles`·`KeywordMaster`.

#### 글유형/디자인

**무엇을 하는 곳인가** — 이 도메인이 어떤 종류의 글을 쓸지 정한다.

**할 수 있는 일**
- 빌트인 글유형 켜기/끄기
- 커스텀 글유형 만들기·복제 (검증된 아키타입을 참조한다)
- 방향성 검증 — 이미 강제되는 규칙과 겹치는지 LLM이 대조해 준다
- 축 값(persona·intent·modifier) 제안받기
- 디자인 지정 (기본은 글유형별 자동 매칭)

**주의** — 폐기된 빌트인 글유형이 있다. 노출 목록에 넣어도 **서버가 걸러내므로 다시 켜지지 않는다.**
어떤 유형이 살아 있는지는 `constants.ts`가 정본이다. 표시는 자리마다 다르다 —
「설정」 탭의 빌트인 노출 카드에서는 취소선과 「사용 중단」 뱃지가 붙고 체크 자체가 막히며,
「글 생성」 탭의 유형 필터에서는 이름 뒤에 「폐기」가 붙는다.

**고칠 때** — `Templates`·`CustomTemplatesManager`·`CustomTemplateForm`.

#### 글 생성

**무엇을 하는 곳인가** — 후보를 만들고, 그중 골라 실제로 글을 쓰게 시킨다. 2단계다.

**1단계 · 글 후보 만들기** — 축을 조합해 후보(슬롯)를 만든다. **LLM을 부르지 않는다.**
글유형과 개수를 고른다. 지역을 쓰는 글유형은 지역을 골고루 돌며 만들고, 다시 누르면
아직 후보가 없는 지역부터 이어서 채운다.

**2단계 · 글 작성** — 버튼이 두 묶음이다.

- **자동 선별** — 「1개 테스트」와 개수가 다른 버튼들. **세 버튼의 선별 규칙은 같고 개수만 다르다.**
  무작위가 아니라 지역·유형을 일부러 벌려 뽑는다.
- **직접 선택** — 목록에서 체크한 후보만 쓴다. 자동 선별과 달리 상태를 보지 않으므로
  **이미 발행된 후보도 다시 쓴다.**

목록에서 후보를 검색·필터하고, 제목을 직접 고치고, 실패한 후보를 **「다시 대기로」** 되돌릴 수 있다.
되돌려야 자동 선별 대상에 다시 들어온다.

**주의** — 요청 개수가 크면 **서버가 여러 작업으로 쪼개** 큐에 넣는다. 등록 알림이 몇 건으로
나뉘었는지 알려준다. 작업 큐 목록이 갑자기 여러 줄이 되는 것은 정상이다.

**고칠 때** — `Slots`, API는 `slots/generate`·`jobs/generate`·`slots/{id}/reset`.

#### 작업 큐 (탭)

`/t/{domain}/jobs`와 같은 내용이다. §3.5 참조.

#### 검수·내보내기 (탭)

`/t/{domain}/posts`와 같은 내용이다. §3.4 참조.

#### 설정

이 도메인만의 설정. 담당은 `Settings`.

- **도메인 정보** — 표시 이름, 브랜드명, 브랜드 컬러, 일일 한도. 업종은 생성 후 바꿀 수 없다
- **빌트인 글유형 노출** — 카탈로그에 어떤 빌트인을 보일지. 폐기된 유형은 여기서 체크가 막힌다
- **구글 색인** — 화면은 있으나 **비활성이다.** 배포 연동 방식이 정해지면 활성화 예정
- **도메인 삭제** — 후보·글 데이터가 함께 지워진다. 되돌릴 수 없다

**주의 — 이름이 두 개고 쓰임이 다르다.** 「표시 이름」은 관리자 화면에서만 쓰는 구분용이라
글에 나오지 않는다. 「브랜드명」은 **글 본문·CTA·내보내기·공개 API에 그대로 나가는 이름**이다.
비워 두면 표시 이름이 그대로 공개된다.

### 3.3 글 생성 `/t/{domain}/generate`

도메인 관리의 「글 생성」 탭만 크게 보여주는 집중 화면. 내용은 §3.2 참조.

---

### 3.4 검수·보내기 `/t/{domain}/posts`

**무엇을 하는 곳인가** — 완성된 글을 확인하고 밖으로 내보낸다.

**할 수 있는 일**
- 글 목록 확인, 제목을 눌러 상세로 이동
- 고른 글을 **Markdown / HTML로 내보내기**
- **색인 요청** 등록 (실제 구글 제출은 아직 보류 상태다 — URL 수집까지만 한다)
- **중복 검사**·**가지치기** 작업 걸기
- 글 삭제

**주의** — **여기 목록에 없다고 글이 사라진 것이 아니다.** 품질 게이트를 통과하지 못한 글은
격리 검수(§3.6)에 따로 쌓인다. "작업은 끝났는데 목록이 비어 있다"면 그쪽을 본다.

**고칠 때** — `Posts`, API는 `posts`·`posts/export`·`jobs/dedup|prune|indexing`.

---

### 3.5 작업 큐 `/t/{domain}/jobs`

**무엇을 하는 곳인가** — 글 작성·중복검사·가지치기·색인 작업의 진행 상태를 본다. 자동 새로고침된다.

**할 수 있는 일**
- 대기·진행·완료·실패 건수와 각 작업의 진행 단계 확인
- 작업 **취소 / 일시중지 / 재개 / 우선 처리**
- 실패한 작업의 오류 메시지 확인

**주의**
- **이 화면은 도메인 하나만 본다.** 워커는 하나뿐이라 다른 도메인 작업이 앞서 있을 수 있다.
  그건 대시보드 표에서 확인한다.
- **취소는 즉시가 아니다.** 워커가 쓰고 있던 글을 마친 뒤 멈춘다. 화면이 "늦어도 언제까지"를 알려준다.
- 작업자가 응답하지 않으면 일정 시간 뒤 자동으로 실패 처리된다. 그때 오류 메시지가
  응답 끊김인지 취소인지를 구분해 적는다.

**고칠 때** — `Jobs`·`JobCard`, API는 `jobs`·`jobs/{id}/cancel|pause|resume|prioritize`.

---

### 3.6 격리 검수 `/t/{domain}/drafts`

**무엇을 하는 곳인가** — **품질 게이트를 통과하지 못한 글**이 버려지지 않고 여기 격리된다.
공개 경로와 분리된 별도 저장소(`draft_posts`)다.

**할 수 있는 일**
- 걸린 품질 이슈 확인
- 본문을 직접 고치고 **다시 검사**
- 통과시켜 **발행**하거나 **반려**
- 삭제

**주의** — 검수·보내기 목록과 **다른 화면이다.** 글이 안 보인다는 문의의 상당수가 이 구분 때문이다.

**고칠 때** — `DraftsClient`, API는 `drafts/*`(`promote`·`revalidate`·`dismiss`).

---

### 3.7 글 상세 `/t/{domain}/post/{postId}`

**무엇을 하는 곳인가** — 글 하나를 실제 렌더 모습으로 확인한다.

**할 수 있는 일**
- 본문(Markdown)과 렌더된 HTML 보기
- 메타 정보 확인
- **「이 글의 근거」** — 그 글이 학원·후기·이미지를 얼마나 썼는지, 「검토 필요」라 못 쓴 값이
  무엇인지 보여준다. 글이 빈약할 때 원인을 찾는 자리다.

**고칠 때** — `PostDetailClient`.

---

### 3.8 운전학원 자료 `/academies`

**무엇을 하는 곳인가** — 학원 자료의 **원본 창고**. 원천에서 받고, AI로 심층조사하고, 사람이 승인한다.

**할 수 있는 일**
- 외부 원천에서 학원 동기화
- AI 심층조사 실행·중단
- 조사값 검토·승인
- 단건 등록 / JSON 일괄 등록

**주의 — 이 화면은 도메인을 모른다.** 학원은 도메인이 아니라 **업종에 딸린 자료**라서 전역 화면이다.
여기서 받은 자료가 곧바로 글에 쓰이는 것이 아니고, **도메인의 「원천 데이터」 탭에서 연결해야**
그 도메인의 글에 쓰인다(§5).

**고칠 때** — `AcademyResearchClient`, API는 별도 컨트롤러(`/api/admin/academy-research/*`).

---

### 3.9 학원 상세 `/academies/{externalId}`

학원 한 곳의 원본 기본정보, 심층조사 필드, 과정별 가격, 셔틀 노선, 원본 후기를 보고
직접 고치거나 승인을 해제한다. 담당은 `AcademyDetailClient`.

**주의** — 수강료·셔틀·운영시간은 **원천이 그 학원 값을 주지 않을 때만** 조사값이 쓰인다.
원천에 구조화된 값이 있으면 그쪽이 이긴다.

---

### 3.10 작업환경 `/settings`

전역 설정. 도메인과 무관하다.

- 운영 튜토리얼 켜기/끄기
- 생성 옵션 기본값
- 업종 관리 — 도메인 생성 시 고를 수 있는 업종 목록. 서버에 저장돼 즉시 반영된다
- 블로그 리뷰 수집 스위치

**주의** — 블로그 리뷰는 **수집만 켜고 끈다. 켜도 글 내용은 달라지지 않는다.**
생성 프롬프트와 품질 게이트에서 이미 빠져 있다. 사유와 재개 조건은 `docs/source-field-usage.md`가 정본이다.

**고칠 때** — `SettingsClient`.

---

### 3.11 관리자 가이드 `/guides` · `/guides/[slug]`

**무엇을 하는 곳인가** — 이 문서를 포함한 가이드를 관리자 화면에서 바로 읽는다.

**중요한 성질 — 사본이 아니다.** 저장소의 `docs/*.md`를 서버에서 그대로 읽어 렌더한다.
화면용으로 옮겨 적지 않으므로 **문서를 고치면 화면도 함께 바뀐다.** 목록에 무엇을 띄울지는
`lib/guides.ts`가 정하고, 마크다운 렌더는 `lib/doc-markdown.tsx`가 맡는다.

**주의** — 그 렌더러는 **가이드 전용이며 생성 글 본문 렌더러와 무관하다.** 글 렌더러는
`post-rendering.ts`와 `scripts/qa-posts.mjs`에 미러로 있고 게이트가 둘을 대조하는데,
이쪽은 그 계약 밖이다. 한쪽을 고칠 때 다른 쪽을 볼 필요가 없다.

배포 이미지에 `docs/`가 빠지면 목록은 뜨되 본문 자리에 안내가 나온다(예외로 죽지 않는다).

---

### 3.12 연동 설정 `/integrations` · 도메인 없음 `/need-domain`

연동 설정은 현재 비활성 안내 화면이다(색인 기능이 보류 상태라 별도 연동 설정이 없다).
`/need-domain`은 도메인이 하나도 없을 때 무엇부터 하면 되는지 안내한다.

## 4. 화면이 보여주지 않는 것

화면만 봐서는 알 수 없어 오해를 부르는 것들이다.

- **글 생성은 즉시 응답이 아니다.** 요청은 큐에 쌓이고 워커가 하나씩 처리한다. 한 건에 수 분이 걸린다.
- **워커는 하나뿐이다.** 다른 도메인의 작업이 앞서 있으면 내 작업은 기다린다.
- **품질 게이트는 화면 밖에서 완성된 글을 검사한다.** 프롬프트로 달래는 것이 아니라 결과물을 막는다.
- **개발 중에는 생성이 끊길 수 있다.** API 소스를 저장하면 워커가 재시작하며 진행 중이던 글이 죽는다.
  자세한 판별법은 `CLAUDE.md`에 있다.
- **글 생성에는 로컬 CLI 인증이 필요하다.** API 키가 아니라 `codex`/`claude` CLI 서브프로세스를 쓴다.

## 5. 자주 헷갈리는 구분

| 헷갈리는 것 | 실제 |
| --- | --- |
| 운전학원 자료 ↔ 도메인의 원천 데이터 | 앞은 **업종 단위 창고**, 뒤는 **이 도메인이 쓰는 자료**. 창고에 있어도 **연결**해야 글에 쓰인다 |
| 검수·보내기 ↔ 격리 검수 | 앞은 **게이트를 통과한** 글, 뒤는 **통과하지 못한** 글. 서로 다른 저장소다 |
| 작업 큐 ↔ 대시보드의 작업 표 | 앞은 **도메인 하나**, 뒤는 **모든 도메인**. 점유 상태는 뒤에서 본다 |
| 도메인 관리의 탭 ↔ 사이드바의 같은 이름 메뉴 | **같은 화면**이다. `view` prop으로 그 부분만 크게 보여줄 뿐이다 |
| 자동 선별 ↔ 직접 선택 | 앞은 규칙대로 고르고 발행된 것을 피한다. 뒤는 체크한 것만 쓰며 **이미 발행된 것도 다시 쓴다** |
| 「글 후보 만들기」 ↔ 「글 작성」 | 앞은 조합만 만든다(LLM 안 부름). 뒤가 실제로 글을 쓴다 |

---

## 6. 이 문서를 고칠 때

- **줄번호와 개수를 적지 않는다.** 편집으로 밀려 엉뚱한 곳을 가리키고, 상수가 바뀌면 거짓이 된다.
  이 저장소는 둘 다 실제로 겪었다.
- **화면 문구를 옮겨 적지 않는다.** 문구의 정본은 `docs/ui-copy-inventory.md`이고,
  거기에는 각 문구가 어떤 코드에 매달렸는지까지 있다. 여기에 복사하면 두 곳이 같이 썩는다.
- **탭이나 메뉴를 늘리면 §1 지도와 §5 구분표를 같이 고친다.** 지도가 낡으면 이 문서 전체가
  신뢰를 잃는다.
- 화면 동작을 바꿨다면 `npm run copy:inventory`로 문구 인벤토리를 다시 만들고,
  `npm run verify:copy-sync`(커밋 훅이 자동 실행)가 통과하는지 확인한다.
